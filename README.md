# Мои практики — платформа

Полноценный трекер практик с админкой, общим каталогом, рейтингом участников и Telegram-напоминаниями. Один сервер, одна база, всё внутри.

## Что умеет

**Для участника:**
- Каталог практик от админа: выбираешь то, что хочешь делать
- Период: неделя / месяц / без срока
- Главный экран «Сегодня» с быстрой отметкой выполнения (факт / счётчик)
- Стрики, история 30 дней
- Рейтинг: где я среди всех по проценту выполнения

**Для админа** (страница `/admin`):
- Создание/редактирование/удаление практик
- Каждая практика: тип (факт или счётчик), цель, иконка, цвет, фото, ссылка на материал
- Настройка напоминаний для каждой практики: 0–10 раз в день, в каком окне (например, 8:00–21:00)
- Статистика: пользователи, активные подписки, отметки за день
- Список всех пользователей

**Бот в Telegram:**
- `/start` — присоединиться, получить кнопку приложения
- `/today` — сводка по сегодняшнему дню без открытия приложения
- `/open` — кнопка-открыть
- `/stop` — отписаться от всех практик и напоминаний
- Напоминания: для каждой невыполненной практики отправляется до N раз в день в заданном окне с равномерным интервалом

## Архитектура

```
server.py            — единственный backend-файл:
                       FastAPI (REST + раздача фронта)
                       Aiogram   (бот, polling)
                       APScheduler (тик каждые 30 минут)
                       SQLite    (общая БД)
frontend/app.html    — Mini App для участников
frontend/admin.html  — админка (для тех, кто в ADMIN_IDS)
requirements.txt
.env.example
```

Аутентификация — через `Telegram.WebApp.initData`: фронт передаёт его в каждом запросе, сервер проверяет HMAC-подпись токеном бота и достаёт `user_id`. Никаких паролей и регистраций.

## Запуск локально

**Разово:**
```bash
git clone <ваш-репо>     # или просто положите файлы рядом
cd practices
pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите:
- `BOT_TOKEN` — от `@BotFather`
- `ADMIN_IDS` — ваш Telegram ID (узнать: написать `@userinfobot` в Telegram)
- `BASE_URL` — пока пропустите, заполним после ngrok

**Каждый раз:**
```bash
# Терминал 1: сервер
python server.py

# Терминал 2: туннель в интернет (Telegram требует HTTPS)
ngrok http 8000
```

ngrok даст URL вида `https://abc123.ngrok.io`. Подставьте его в `.env` как `BASE_URL` и перезапустите сервер.

## Подключение бота к приложению

В чате с `@BotFather`:

1. `/setdomain` → выбираете бота → отправляете URL **без** `https://` (например `abc123.ngrok.io`)
2. `/newapp` → выбираете бота → название («Практики») → описание → загружаете иконку (640×360) и photo (любая) → URL приложения = `<BASE_URL>/app` → короткое имя `tracker`

Готово. Прямая ссылка на приложение: `https://t.me/<имя_бота>/tracker`.

Опционально через `@BotFather`: `/mybots` → бот → `Bot Settings` → `Menu Button` → задать постоянную кнопку «Открыть практики».

## Деплой 24/7

Локальный ngrok отрубится — для постоянной работы нужен хостинг.

**Render.com (бесплатно):**
1. Положите код на GitHub (приватный репозиторий ОК)
2. На Render → New → Web Service → подключить репо
3. Build command: `pip install -r requirements.txt`
4. Start command: `python server.py`
5. Environment Variables: `BOT_TOKEN`, `ADMIN_IDS`, `BASE_URL` (Render даст домен после первого деплоя — сначала задеплойте с любым URL, потом обновите), `TZ`
6. Render даст URL вида `https://practices-xxx.onrender.com` → положите его в BASE_URL и обновите в @BotFather (`/setdomain` и `/editapp`)

⚠️ На бесплатном Render процесс «засыпает» через 15 минут без запросов — напоминания будут пропускаться. Для продакшена нужен платный план ($7/мес) или Fly.io / VPS.

**Fly.io / Railway / собственная VPS** — аналогично, нужны эти же три переменные окружения.

## Как пользователь добавляет себе практику

1. Открывает бота, жмёт «✨ Открыть практики» (или меню-кнопку)
2. В приложении — таб **Каталог**
3. Выбирает практику → лист снизу с вопросом «На какой период?»
4. Нажимает «Присоединиться»
5. Дальше она появляется в табе **Сегодня**

В любой момент можно добавить ещё. Период истекает — практика просто перестаёт показываться, история сохраняется.

## Логика напоминаний

Каждые 30 минут планировщик смотрит:
- У всех активных подписчиков всех практик
- Если сегодня ещё не выполнено
- И не достигнут лимит напоминаний на эту практику
- И сейчас в окне `reminder_from`–`reminder_to`
- И прошёл минимальный интервал с прошлого напоминания (равномерно делится окно на N напоминаний)

Если бот заблокирован пользователем — его подписки автоматически снимаются, чтобы не спамить.

## Рейтинг

Считается по проценту: `выполненные дни / (число активных практик × дней в периоде)`.

Юзер без активных практик в рейтинге не показывается. Топ-3 получают медали 🥇🥈🥉.

> Это упрощённая модель — плановое количество не учитывает реальные даты подписки на каждую практику. Для серьёзной соревновательной задачи стоит перейти на более точный расчёт «практико-дней с учётом интервалов подписки» — править в `server.py` функцию `leaderboard()`.

## Безопасность

- `BOT_TOKEN` — секрет; держите в env-переменных, не коммитьте `.env`
- Все API эндпоинты требуют валидный `X-Init-Data`. Подделать его нельзя без знания `BOT_TOKEN` (проверка через HMAC-SHA256)
- Админские эндпоинты дополнительно проверяют, что `user_id ∈ ADMIN_IDS`

## База данных

SQLite-файл `data.db` рядом с `server.py`. Бэкап = просто скопировать этот файл. На бесплатном Render файловая система эфемерная — при перезапуске сервиса БД может потеряться. Для продакшена либо платный план с persistent disk, либо переехать на Postgres (заменить `sqlite3` на `asyncpg`/`psycopg`).
